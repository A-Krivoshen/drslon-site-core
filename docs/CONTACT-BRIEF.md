# Contact dialogs

The filename `includes/contact-brief.php` stays so the existing plugin require
keeps working. The brief form is gone. The file renders a contact block:

- heading: «Есть задача? Давайте обсудим»
- «Написать в Telegram» opens `https://t.me/DrSlon?text=...`
- «Написать в MAX» opens the existing personal profile via `/max`
- email and phone stay under the buttons

There is no form, endpoint, database row, clipboard step or registration.
The visitor is not asked to copy a message or pick a chat.

Telegram is the personal dialog `@DrSlon`, not a channel and not `t.me/share`.
The draft is short: greeting, service name, and the selected package when a
price card supplied `data-krv-package` or `data-krv-need`. JavaScript keeps a
line break. The no-JS WordPress href is one line, because `esc_url()` removes
`%0A`. MAX has no prefilled personal-message parameter, so the link only opens
the profile.

`id="brief"` stays. Existing «Обсудить задачу» links still scroll there.
A card click replaces the previous package. A plain `#brief` click does not.

Canonical assets:

- `assets/js/contact-talk.js`
- `assets/css/contact-talk.css`

Standalone copies on the six static landings and Flask are generated by
`tools/sync_contact_assets.py` in the optimization workspace. Keep them
byte-identical. `contact-brief.js` and `contact-brief.css` are unused.

A messenger click is `cta_telegram` or `cta_max`. Phone and email keep
`contact_phone_click` and `contact_email_click`. Parameters are the service
slug, the pathname, and an allowlisted package slug. No message text, name or
contact is sent. `contact_open`, `brief_start`, `brief_prepare`, `brief_copy`
and `qual_submit` are not fired. `krv-lift.js` no longer counts the same
messenger click. When `window.krvConsent` exists, goals fire only if
`analytics === true`. Legacy landings without that object fire only when `ym`
is already a function. No second counter is created.
